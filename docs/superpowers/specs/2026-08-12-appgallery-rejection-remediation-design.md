# AppGallery 审核驳回统一整改设计

## 背景与目标

AppGallery 对 `LED滚动字幕` 1.0.0 的审核报告列出 6 项问题，其中 4 项阻断上架，2 项建议优化。本轮采用已批准的“最小完整整改”：解决全部 6 项，不重做应用视觉或功能，不改变包名、版本、签名配置或 AGC 应用标识。

应用唯一对外名称为 `光迹字幕`。安装包、启动器、最近任务、应用内协议与商店资料必须使用同一名称和同源图标视觉。

## 问题映射

| 审核问题 | 根因 | 整改 |
|---|---|---|
| 名称广义、缺乏识别性 | AGC 商品名仍为 `LED滚动字幕` | 保持包内 `光迹字幕`，在外部提交阶段同步 AGC 商品名、介绍、隐私资料与软件资质 |
| AGC 图标存在透明背景 | 商店上传图标不符合全画布不透明要求 | 从现有分层图标源导出 1024×1024、全画布不透明、无预切圆角的商店 PNG，并验证 alpha |
| 商店与安装后名称/图标不一致 | AGC 资料与当前包内身份不一致 | 商店资料改为 `光迹字幕`，商店图标与包内分层图标使用同一生成源 |
| 隐私模块名称不一致 | AGC 商品名与包内/协议名称不一致 | 统一为 `光迹字幕`，复查隐私政策、用户协议及平台隐私模块；开发者名称以 AGC 当前主体为准 |
| 空历史页“清空”对比度不足 | 无记录时仍以 45% 透明度渲染不可用文字 | 无历史记录时不渲染“清空”；有记录时以正常高对比度显示并保留确认流程 |
| 点击完成时延 3117ms | 被审包早于当前即时导航和后台持久化改动 | 重新构建当前代码，并在可用设备上按 T2-T1 复测，目标不超过 900ms |

## 本地实现

### 历史页空状态

`HistoryPage` 标题栏始终保留返回、标题和右侧布局空间。仅当 `records.length > 0` 时构建可交互的“清空”文字；空状态不生成该控件，因此不存在低对比度禁用文字或误触入口。有记录时继续显示确认弹窗，确认后先更新可见列表，再后台持久化。

### 商店图标产物

扩展现有确定性图标生成脚本，复用同一背景层和前景层生成商店图标。成品为 1024×1024 PNG，背景覆盖整个画布，alpha 通道每个像素均为 255，不提前裁成圆角，也不修改 AppScope 或 EntryAbility 的分层图标引用。商店成品放入发布资料目录，不作为新的运行时图标资源。

### 名称和隐私一致性

包内 AppScope、EntryAbility、首页标题、隐私政策和用户协议继续使用 `光迹字幕`。新增或扩展静态合同，拒绝旧名称重新进入包内和发布文档。AGC 商品名、介绍、隐私模块、软件资质及开发者主体的一致性属于外部提交操作，在真正保存前单独确认。

### 点击性能

不新增第二套性能实现。沿用当前“先导航或更新 UI，再后台写 Preferences”的代码路径，重新构建包含该修复的最新包。静态合同只能证明调用顺序，最终结论必须由运行时测量给出；未测设备一律记为 `unverified`。

## 回归与验收

- 历史页合同：空记录状态不渲染“清空”，有记录时仍可清空且保留确认弹窗。
- 图标合同：商店 PNG 为 1024×1024、全像素不透明、无预切圆角，并与包内前景/背景生成源一致。
- 身份合同：包内和发布文档中应用名称为 `光迹字幕`，不出现旧商品名作为当前名称。
- 性能合同：展示、颜色确认、计数和历史记录操作保持即时可见；设备测量点击完成时延不超过 900ms。
- 执行 `scripts/check-standard.ps1` 与 `scripts/build-harmony.ps1`，记录构建产物、哈希和已连接 phone/tablet/2in1 结果。
- `build-profile.json5` 中既有签名材料不读取、不复制、不清理、不修改；相关 AppGallery 合同若仍因此失败，按既有外部阻断如实记录。

## 外部提交边界

本地整改完成后，AGC 的名称、图标、介绍、隐私资料、资质、包上传和重新提审仍是独立外部写入。执行这些操作前，需再次说明将写入的具体字段和文件并取得确认。不得擅自修改包名、版本号、签名、应用 ID 或开发者主体。
