## 文件设计

新增 `references/release-preflight-cases.md`，集中存放高频上架案例和发布前决策流程：

1. 布局错位、截断、变形、模糊、弹窗遮挡，以及弹窗可关闭或点击空白消失的证据要求。
2. 底部固定控件、输入键盘、悬浮按钮、滚动末端、弹窗和半模态的导航区域适配检查；将 FAQ 的 28vp 作为该 FAQ 的检测操作说明，并要求以实际系统 inset 和当前官方标准复核，避免把固定值错误泛化到所有系统状态。
3. 深色模式下字体、图片、组件背景、状态栏、图标、遮罩、弹窗及动态内容的完整检查。
4. 状态栏背景融合、图标明暗、分栏背景和各主题页面证据。
5. AppGallery 分类、二级分类和标签必须匹配应用实际核心功能，不得仅凭名称或期望流量选择。
6. APP 备案、经营性互联网信息服务许可、非必选软件著作权保护材料及特殊行业资质的适用性判断；资质清单保持实时路由，不复制易过期的行业长表。
7. AppGallery Connect 资质材料上传位置、材料真实性/有效期/主体/业务范围一致性和敏感信息保护要求。

更新 `SKILL.md`：

- 在 description 中补充分类、标签、备案、资质、深色模式、系统栏和安全区域等触发语义。
- 在 Required Reference 中为高频驳回案例和发布前分类/资质检查增加精确路由。
- 在 workflow 中先查产品实际能力和分类，再判断资质适用性；未知或需法律判断的内容标记 `unverified` 并要求实时官方核验。

更新 `agents/openai.yaml` 的短描述和默认提示，使默认审查明确包含发布前分类与资质核对，但保持内部 ID 和展示名不变。

## 去重规则

- 同一官方要求只在权威 reference 中定义一次。
- FAQ 只记录判退示例、测量口径、工具或补充操作，不覆盖 UX 标准和审核指南的等级、范围或阈值。
- 分类和资质清单随政策变化较快，只保存决策流程、入口和来源日期；具体类别和材料必须读取实时官方页面。
- 页面没有可核实正文、链接失效或内容冲突时，不新增事实；报告为 `unverified` 并说明原因。

## 验证

1. 运行 skill 结构验证，确认 frontmatter、资源路径和 `openai.yaml` 有效。
2. 扫描来源 URL、标题、日期和重复阈值，确保 50104、色彩阈值及既有 UX 条目未被复制。
3. 验证代表性请求：
   - 底部导航判退应检查五类遮挡场景、实际 inset、沉浸背景及全屏恢复。
   - AppGallery 发布前审查应先匹配分类/标签，再判断备案和资质适用性，不输出整份无关行业清单。
   - 深色模式审查应覆盖所有视觉表面和系统栏，未运行主题切换时不得判 `pass`。
4. 执行项目标准检查和构建；skill 不改变运行时，因此没有新设备 UI 行为需要验证，设备可用性仍按项目现状记录。
5. 回填 `tasks.md`、`changes.md`、`design.md` 和 `design-qa.md`，记录已纳入、已省略及无法核实的来源。
